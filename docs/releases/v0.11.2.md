## The desktop app starts again after an in-app update

0.11.1 locked down the server's data folder so other accounts on the PC can't read it. The in-app updater downloads a new version into that folder and then moves it into `C:\Program Files\LANcast`, and a moved file keeps its permissions. So every update applied by 0.11.1 leaves `LANcast.exe` and its libraries readable only by administrators. The server keeps running, but **the desktop window and the tray icon can't start**, and Windows says "Access is denied".

This release fixes it in two places:

- **The updater gives each new file the program folder's normal permissions** as it moves it in. If it can't, it doesn't install that update, rather than leave the app unable to start.
- **The server repairs its own program files every time it starts.** An update is applied by the version you're leaving, so the update to 0.11.2 is installed by 0.11.1's updater and still arrives locked. 0.11.2's server unlocks those files the first time it starts, before you open the window.

## Updating

**From 0.11.1, use the in-app update as usual.** When it has finished, give the server about half a minute to start, then open LANcast. If the window still won't open, run this once from an administrator PowerShell, then open LANcast again:

```
icacls "C:\Program Files\LANcast\*" /reset
```

From 0.11.0 or earlier, nothing changes: use the in-app update, or run **`LANcast-Setup-0.11.2.exe`** from anything older than 0.9.79. Everything in the [0.11.1 notes](https://github.com/Conqueror-Mod/LANcast/releases/tag/v0.11.1) still applies, including the ffmpeg step and the one-way database change (revision 97), which this release does not change again.
