## The first 1.0 candidate

Before 1.0, every part of LANcast was reviewed against a written checklist: sign-in, file serving, federation, playback, the desktop window, the installer, the updater, retro games, the client and the rest. The review found 18 serious faults, 39 significant ones and over 70 smaller ones. **Every one marked for 1.0 is fixed in this release**, and the ones that involve the installed service were checked on a real installed server, not only in tests. There are no new features: from 0.11.0, features wait until after 1.0.

## Security

- **The server's data folder is locked down on Windows.** `C:\ProgramData\LANcast` used to keep Windows' defaults, so any account on the PC could read the database, the server's keys and the backups, and could add files that the service would later trust. It's now readable only by SYSTEM and Administrators. The first start after updating takes 20–40 seconds longer while the folder is fixed, once.
- **On Linux the data folder is now its owner's alone** (mode 0700). The database was readable by every account on the machine.
- **The service runs ffmpeg only from a protected folder.** A copy of ffmpeg that an ordinary account could replace was a way to run code as SYSTEM. See *Updating* if you installed ffmpeg yourself.
- **The face worker runs only from beside LANcast.exe** as the service, for the same reason.
- **A server proves who it is over the connection.** The desktop window checks the server's identity key, not only its certificate, and a certificate that changes without the key is refused rather than clicked through.
- **The updater checks the update again just before installing it**, so a file swapped after the download is refused.
- **A restore refuses a backup LANcast did not write.** Restoring a backup also signs everyone out and clears API keys and passkeys, as it already did sessions. Two-factor recovery codes are kept.
- **Sign-in is harder to attack:** a failed guess slows down only the account it was aimed at, sign-in takes the same time whether an account exists or not, a stranger can no longer fill the server with passkey challenges, invite links are throttled before any expensive work, and minting an API key now asks for your password. When an administrator resets someone's password, that person's API keys are revoked.
- **No cross-site requests before the first account exists**, and a running conversion is served only to the account that started it.
- **Files people bring are handled more carefully:** a subtitle download can only write inside its own folder, a picture claiming a huge size never reaches the decoder, a game with a bad icon no longer crashes the window, and a plugin call has a time limit and a memory cap.
- **Turning off "visible to friends" now hides you completely.** Before, people you had shared your viewing with one by one could still see what you were watching.
- **Connections use post-quantum key exchange.** Browsers, the desktop window and paired servers all agree keys with X25519MLKEM768. A test now stops this being switched off by accident.

## Playback

- **A film you stop stops converting.** Leaving a film, switching titles or closing the tab now ends its conversion at once. Before, it ran on for up to ten minutes and slowed every title opened meanwhile.
- **Changing Quality or the audio track before a film starts now takes effect.** It used to keep the conversion already running.
- **Films at unusual frame rates play to the end.** Some listed too few segments and stopped early.
- **The bit-rate ceiling holds** for files whose bit rate was never measured.
- **Films stored with a metadata provider's running time instead of the file's real length are measured again** after updating. A wrong length made a converted film stop early: one stopped at 16 minutes of a two-hour film.
- **Deleting a film in LANcast while it is converting works**: the conversion is stopped first. A file another program holds open keeps its place in the library instead of vanishing and coming back as a stranger.
- **Subtitles:** a converted subtitle follows its source when the file changes, and a UTF-8 subtitle cut at an awkward point is no longer mistaken for binary.

## Your edits stay put

- **A rescan never overwrites a field you locked**, including a book's part order and a locked book's sort title.
- **A playlist you edited is never re-imported** from its file.
- **A scan that could not read a folder never empties the trash.** An unreadable drive no longer looks like deleted files.
- **A game save the player could not fetch is never overwritten.**
- **Library limits fail closed**, and profiles, shared activity and listings respect them.

## Smaller fixes

- **Titles in any script can match** metadata (Japanese, Korean, Cyrillic and others).
- **The service restarts itself after a failed start.**
- **Reset settings** keeps your outside credentials, such as provider keys.
- **The client:** a partial delete refreshes every list, the downloads list belongs to each account on a shared device, revoking an API key asks you to confirm, and more than a dozen smaller faults in playback, settings and the player are fixed.
- **Indexing photos for search** refuses a second run while one is going, instead of starting two.

## Updating

From 0.9.79 or later, use the in-app update. From anything older, run **`LANcast-Setup-0.11.1.exe`**.

- **If you installed ffmpeg yourself** (for example with winget), the service may now say it is "Not used", because it lives in a folder any account can change. Press **Download ffmpeg** in Settings › Server › Transcoding, or run `LANcast.exe service tools` once from an administrator PowerShell. Until you do, films that need converting won't play.
- **Reading the log or database by hand now needs an administrator shell.** Settings › Troubleshooting › Server log still shows the log in the app.
- **On Linux, run `sudo lancast service install` again** after replacing the binary. The unit earlier versions wrote started the desktop launcher instead of the server, so it never answered on its port.
- **This release changes the database** (revision 97). Once 0.11.1 has started, an older version can't open it, so update forward. A backup is taken automatically before the change.

## Known issues

- **An AC3 or DTS film at Original quality in a browser can take about two minutes to start**, while the audio is converted. Choosing a lower quality starts it at once.
- **Deleting a film in File Explorer while LANcast is converting it fails**, because ffmpeg holds the file open. Stop the film first, or delete it from inside LANcast.
