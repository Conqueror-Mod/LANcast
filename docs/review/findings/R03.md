## R03-1 Any signed-in account can fetch another account's converted film, segment by segment

- **Severity:** S1
- **Class:** other (object-level permission; touches C5 and C7)
- **Confidence:** high
- **Where:** `internal/api/transcode.go:183` (`hlsSegment`), `internal/api/transcode.go:298` and `internal/api/server.go:1086` (`GET /api/transcode`)
- **Failure:** Given an administrator is watching a converted film that a member's rating ceiling or hidden library keeps from them, the member calls `GET /api/transcode` and receives every running session's `id`, `item_id` and `owner`. The member then calls `GET /api/stream/1/hls/<that id>/init.mp4` and `…/seg00000.m4s`, `seg00001.m4s` and so on, and receives the film. The `{id}` in the path can be any number: the handler never looks it up.
- **Evidence:**
  - `hlsSegment` reads `session` and `name` from the path, validates the name, finds the session with `s.trans.Session(sessionID)` and serves the file. It makes no `GetItem` call, does not compare `sess.ItemID` with the path's item, and does not compare `sess.Owner` with the caller. The existing `hlssegment_test.go` runs the handler on a `Server` whose store is nil, which only works because no permission lookup happens.
  - `GET /api/transcodes` is admin-only, with the comment "a conversion names an account and a film, so the list is a list of who is watching what". `GET /api/transcode` (singular) returns the same `transcode.SessionInfo` list (`ID`, `ItemID`, `Owner`) and is registered with no wrapper. Nothing in `web/src` calls it.
  - Session ids are 8 random bytes (`newID`), so the listing is the only practical way to learn one. That is why this is a member problem. A guest or a paired server passes the item check for a shared item and then reaches the same handler, so a session id learned any other way would open another item's segments to them too, but neither can list ids.
  - Scratch test, passed:

    ```go
    func TestR03MemberListsEveryConversion(t *testing.T) {
        h := newHarness(t)
        h.secure(t, "a good long password")
        kid := limitedMember(t, h, "kiddo", "PG")
        resp := h.doAs(t, kid, "GET", "/api/transcodes", nil)
        resp.Body.Close()
        if resp.StatusCode != http.StatusForbidden {
            t.Fatalf("admin list for a member = %d, want 403", resp.StatusCode)
        }
        resp = h.doAs(t, kid, "GET", "/api/transcode", nil)
        resp.Body.Close()
        if resp.StatusCode != http.StatusOK {
            t.Fatalf("GET /api/transcode for a member = %d", resp.StatusCode)
        }
    }
    ```

    Output: `a PG-limited member got 200 from GET /api/transcode`.
  - The segment half was not run end to end, because it needs a real ffmpeg session. It rests on the code above.
- **Fix sketch:** In `hlsSegment`, refuse unless the session's item is the item in the path and the session's owner is `s.streamOwner(r)`; check how live-channel sessions set `ItemID` first, since `/api/channels/{id}/hls/…` shares the handler. Make `GET /api/transcode` admin-only, or cut its answer for non-admins to `available` and `encoder`. Update `docs/api.md` and `docs/openapi.json` in the same change.
- **Verdict:** CONFIRMED. The listing is proven by test. For the segment route I looked for a guard in `requireAuth`, the guest gate, `federationPlay` and the mux and found an item check only for guests and peers, and that one checks the path's item, not the session's.
- **Triage:**

## R03-2 Moving the optimized folder leaves every copy offered and none servable

- **Severity:** S2
- **Class:** other
- **Confidence:** high for the server; the client's reaction to the 503 was not checked (R14)
- **Where:** `internal/api/optimized.go:60` (`optimizedDir`), `:342` (`optimizedFor`), `:356` (`serveOptimized`); `internal/api/settings.go:494`
- **Failure:** Given finished copies exist and an administrator changes `optimized_dir` (or a copy's file is removed from disk by hand), `GET /api/items/{id}/playback` still answers `version: "optimized"` with a direct-play decision, because it reads only the database row. `GET /api/stream/{id}?version=optimized` then answers `503 the optimized copy is missing from disk`, because it looks in the new folder. Every device that was preferring the copy is sent to a file the server cannot serve, while the live conversion that would have worked is never offered.
- **Evidence:** `optimizedFor` calls `ReadyOptimized` and unmarshals the stored probe; it never stats the file. The settings handler validates the new folder and saves it; nothing moves the files, clears the rows, or re-queues them. Two side effects follow: the old folder's files are never swept, because `sweepOptimized` reads only the current folder, and `OptimizedBytes` still counts the rows, so the size limit stays "used" by copies that cannot be played. Scratch test, passed:

  ```go
  func TestR03MovedFolderOffersACopyItCannotServe(t *testing.T) {
      h := langHarness(t)
      id := h.addFile(t, "uhd.mkv", []byte("original"))
      h.probeAsHEVCWithTwoAudioTracks(t, id)
      readyCopy(t, h, id, "the copy")
      cur := h.settings.Get()
      cur.OptimizedDir = t.TempDir()
      if err := h.settings.Set(cur); err != nil {
          t.Fatal(err)
      }
      var a struct {
          Version  string         `json:"version"`
          Decision probe.Decision `json:"decision"`
      }
      decode(t, h.authed(t, "GET", fmt.Sprintf("/api/items/%d/playback", id), nil), &a)
      resp := h.authed(t, "GET", fmt.Sprintf("/api/stream/%d?version=optimized", id), nil)
      resp.Body.Close()
      if a.Version != "optimized" || resp.StatusCode != http.StatusServiceUnavailable {
          t.Fatalf("not reproduced")
      }
  }
  ```

  Output: `playback says version="optimized" method=direct; the stream it names answers 503`.
- **Fix sketch:** Have `optimizedFor` confirm the file exists before offering the copy, and mark the row failed or queued when it does not. On a change of `optimized_dir`, either move the files or re-queue the ready rows.
- **Verdict:** CONFIRMED by test. `web/src/playback/PlaybackProvider.tsx:270` adds `version=optimized` whenever the playback answer said so; whether the player recovers from the 503 belongs to R14.
- **Triage:**

## R03-3 The optimized sweep deletes files it did not write

- **Severity:** S3 (the precondition is narrow, but the result is a deleted file, so triage may want it higher)
- **Class:** other
- **Confidence:** high
- **Where:** `internal/api/optimized.go:320-337` (`sweepOptimized`)
- **Failure:** Given `optimized_dir` is set to a folder that already holds a file named with digits and `.mp4`, such as `300.mp4`, `1917.mp4` or `0001.mp4`, the sweep deletes it within 30 seconds, because no optimized row has that number as an item id. The check that refuses a folder inside a library does not cover an ordinary video folder outside one.
- **Evidence:** The sweep decides a file is "ours" with `fmt.Sscanf(name, "%d.mp4", &id)`, and its comment says "not ours; leave anything else in the folder alone". `Sscanf` matches a prefix, so `12.mp4.bak` also matches, and then the file removed is `12.mp4`, not the one listed. Scratch test, passed:

  ```go
  func TestR03SweepRemovesAFileThatIsNotACopy(t *testing.T) {
      h := newHarness(t)
      dir := t.TempDir()
      mine := filepath.Join(dir, "300.mp4")
      if err := os.WriteFile(mine, []byte("somebody's own film"), 0o644); err != nil {
          t.Fatal(err)
      }
      cur := h.settings.Get()
      cur.OptimizedDir = dir
      if err := h.settings.Set(cur); err != nil {
          t.Fatal(err)
      }
      h.srvAPI.sweepOptimized(context.Background())
      if _, err := os.Stat(mine); !os.IsNotExist(err) {
          t.Fatalf("not reproduced: %v", err)
      }
  }
  ```

- **Fix sketch:** Give copies a name nothing else uses (a prefix or a different extension), match the whole name exactly, and refuse an `optimized_dir` that is not empty when it is first chosen.
- **Verdict:** CONFIRMED by test. `checkOptimizedDir` was read for a guard and has none for this.

## R03-4 A file being streamed cannot be deleted or replaced on Windows, and an in-app delete then loses the row but keeps the file

- **Severity:** S3
- **Class:** C10
- **Confidence:** high for the mechanism; not reproduced on a running server
- **Where:** `internal/api/stream.go:97`, `download.go:54`, `extras.go:218`, `preroll.go:116`, `optimized.go:366`, `photo.go:64`, `romsaves.go:130`, `dlna.go:351`
- **Failure:** Given somebody is direct-playing a film (or has it paused, or their connection has stalled), the server holds the file open through `os.Open` for as long as the response lasts. Explorer refuses to delete, rename or replace that file. If an administrator deletes the title in LANcast at that moment, `os.Remove` fails, the failure is only logged (`delete file failed`, `items.go:224`), the row is removed anyway, and the next scan adds the film back.
- **Evidence:** Go's `os.Open` on Windows opens without `FILE_SHARE_DELETE`; the repo already says so in `internal/comic/openshared_windows.go` and works around it for `.cb7` only. The HTTP server sets no write timeout, so a response to a client that has stopped reading is held until the connection drops. A native player keeps one connection for a whole film.
- **Fix sketch:** Move `openShared` out of `internal/comic` into a small shared package and use it for every file served by `http.ServeContent`. Test a delete during a read, as the `.cb7` fix did.
- **Verdict:** PLAUSIBLE. The handle semantics and the delete path are read from code; the full sequence was not run, because it needs a server and the task forbids starting one.
- **Triage:**

## R03-5 A game save can be on disk with no row, or with the wrong row

- **Severity:** S3
- **Class:** C16
- **Confidence:** low
- **Where:** `internal/api/romsaves.go:245-268` (`putSave`)
- **Failure:** `putSave` writes the save file, which also rotates the current file to `.prev`, and only then writes the row with `PutROMSave(r.Context(), …)`. Given the player closes its connection after sending the body (a save on exit) or the database is busy, the row write fails after the files have changed. For a first save there is then no row, and `GET …/saves/{slot}` answers 404 although the bytes are on disk, so the game starts without its save. For a later save the row still describes the older bytes (its SHA-256, and for a save state its core and version) while the newer file is served under it; a retry rotates again and overwrites the real previous copy.
- **Evidence:** `saves.Files.Write` renames `cur` to `prev` and the temporary file to `cur` before returning. `PutROMSave` is a single statement run on the request's context. `getSave` answers 404 when `GetROMSave` finds no row, before it looks at the disk. `raplay.go:151` already detaches from the request's context for the same reason ("a player closing mid-award must not cancel the award").
- **Fix sketch:** Record the row on a context that outlives the request, and undo the rename when the row cannot be written.
- **Verdict:** PLAUSIBLE. The ordering is certain; whether the desktop player ever closes before the answer was not checked (R11, R12).
- **Triage:**

## R03-6 DLNA answers without limits for a few seconds after its account is cleared or deleted

- **Severity:** S3
- **Class:** other
- **Confidence:** low
- **Where:** `internal/api/dlna.go:92-103` (`cfg().Account` read per request), `dlna.go:164` (`ceiling, _ :=`), `internal/serverapp/dlna.go:104-123`

Both mean "no limit": `HiddenLibraries` returns nothing and the ceiling is empty, so `/dlna/media/{id}` serves any file in any library to any device on the LAN, with no sign-in. - **Fix sketch:** In `DLNAHandler`, answer 503 when the configured account is empty or no longer exists, and treat a ceiling lookup error as a refusal.
- **Verdict:** PLAUSIBLE. The window is short and LAN-only, and the media route's own `GetItem` still applies once the account is a real one.

**Who may fetch each file.** Every item route in the slice starts with `GetItem(id, userID)`, which applies the ceiling and hidden libraries, or with `GetFace`, which does the same. The exceptions are `hlsSegment` (R03-1), `streamPreroll` and `serveArtwork`, which are open to any signed-in account by design (a clip the owner chose; an image named by the hash of its bytes). The guest allow-list holds only the stream, transcode, HLS and subtitle routes, each with an item check, so a guest reaches none of download, extras, photo, pages, game files, saves, pre-roll or backups.

**Stream tickets.** Scope (`ticketRoute`): `GET`/`HEAD /api/stream/{id}` for the ticket's own item; for a game's ticket also its file list, files, the minting person's saves and its RetroAchievements posts. The id must be in canonical form, a trailing slash is refused, and any other path is not a credential. Expiry is 24 hours, checked on every use. The minting credential is looked up again on every use, so signing out, a password change or a revoked key ends the ticket. Presented in a header only, stored hashed, in memory. The item's visibility is checked again by `GetItem` on every request. Clean.

**Range requests.** Every file goes out through `http.ServeContent` or `http.ServeFile`, including the comic page from a byte reader. The progressive conversion sends `Accept-Ranges: none`. Clean.

**Filesystem browse.** `GET /api/browse` is `adminOnly`. It lists folders, skips dotfiles and hidden folders, and never returns a file or its contents. Clean.

**Backups.** List, create, download, delete and restore are all `adminOnly`. Names are validated by `Resolve` before any open, delete or stage. Restore inspects the snapshot, takes a safety backup first, and unstages if the restart fails. Two restores started at the same moment could both pass the `Staged()` check; not filed, since both stage the same kind of marker and an administrator did both.

The web-core install runs on `context.Background()` and is stopped only by the cancel route or the process ending; not filed. The server has no write timeout, which is part of R03-4.

**C17.** Tickets are random 32 bytes, kept as hashes, never in a URL. The RetroAchievements key and token are sealed, and the token is redacted from answers. Containment failures log the row's path, which is not a secret.

**C7.** Not audited route by route; `apidoc_test.go` and `openapi_test.go` cover paths. One gap noted in R03-1: `docs/api.md` does not say who may call `GET /api/transcode`.

**`internal/contain`.** Lexical and resolved checks both apply; junctions are followed by a hand-written walk; a dangling link is refused; a path that does not exist yet resolves its nearest ancestor; `EntryWithin` judges a link by its folder and refuses the root itself. The check-then-open gap is documented as out of scope in the package comment. Clean.
