## R16-1 Dialogs opened from a tile or the detail page cannot be reached with a remote

- **Severity:** S2
- **Class:** other (focus and keyboard)
- **Confidence:** high
- **Where:** `web/src/components/RemoveDialog.tsx:24`, `AddToPlaylist.tsx:36`, `ChoosePoster.tsx:31`, `FixMatch.tsx:111`, `EditDescription.tsx:29` (and `PosterTile.tsx:403`)
- **Failure:** On a television (big-screen mode, a remote sending arrows, Enter and Escape), focus a film in a library grid, press the actions key, and choose "Remove from library…". The Remove dialog opens, but focus is put back on the tile *behind* it (`PosterTile`'s menu `onClose` calls `openedFrom.current?.focus()` when the menu was opened by key). The dialog's buttons are plain `<button>`s that nothing registers with the focus controller, and the dialog pushes no focus scope. So the arrows walk the grid behind the dialog, and Enter opens whichever tile is focused, navigating away. The dialog's two choices cannot be pressed at all. Escape still closes it. The same happens with "Add to playlist…" from a track tile, and on the detail page with Fix match, Choose poster and Remove, where focus stays on the button that opened the dialog. `EditDescription` autofocuses its text box, so it can be typed into, but its Save button has the same problem.
- **Evidence:** `FocusController.onKeyDown` resolves arrows and Enter only among registered entries (`nearest(..., entries.current, ...)`), and Enter calls the *current entry's* `onSelect`. The only components in the slice that make a dialog reachable this way are `PictureEditor` (which uses `useFocusZone` and `useFocusScope`, `PictureEditor.tsx:57`) and the menus (`useSuspendFocus` plus their own arrow handling, `Menu.tsx:81`). `grep useFocusScope|useFocusZone components/` finds `PictureEditor.tsx` and nothing else. Settings panes escape this because `Settings.tsx:279` wraps them in a focus zone, whose MutationObserver registers a dialog's buttons when it appears. A tile grid and the detail page have no zone.
- **Fix sketch:** Give the shared dialogs the `PictureEditor` treatment: a ref that applies `useFocusZone` and `useFocusScope` to the dialog box, and move focus to its first control on mount. One small `useDialogFocus()` hook used by all of them keeps the next dialog from repeating this.

## R16-2 The queue panel marks every copy of a repeated track as playing, and keys its rows by id

- **Severity:** S3
- **Class:** other (lists keyed by id)
- **Confidence:** high
- **Where:** `web/src/components/QueuePanel.tsx:233` (key), `:240` (`current={id === currentID}`), `:107` (`at = ids.indexOf(currentID)`)
- **Failure:** Play a playlist that holds the same song twice (positions 2 and 9; ADR 0030 allows it). When position 9 is playing, the queue panel (player popover, Now Playing's Queue tab, the pop-out player) highlights **both** rows as the current one, and its window is centred on position 2. In a long playlist (over 300 rows, where the panel windows the list) the window is placed around the first copy, so the row actually playing can be outside it. The rows are keyed `key={id}`, so React sees two children with one key. React warns, and on an update that moves the window it may drop or reuse the wrong row: the list somebody is reading can lose a row, which is the failure `CLAUDE.md` names ("anything that keys a playlist on item id silently shortens it"). The "Up next" lane in the same file already keys by position (`:210`), and the comment beside the main list says two rows can carry the same track, so the main list is the one place that was missed.
- **Evidence:** `QueuePanel` takes `currentID: number` and nothing else about where the cursor is. Its three callers pass `pb.itemID` (`NowPlaying.tsx:144`, `Player.tsx:1118`, `PopoutPlayer.tsx:166`). `PlaybackProvider` keeps a position cursor (`pos`, `PlaybackProvider.tsx:576`) that the panel never receives.
- **Fix sketch:** Key rows `${id}@${i}` as the lane does. Pass the cursor position (`pb` already has it) and mark `current` by `i === pos`, centring the window on it.

## R16-3 Episode air dates show one day early west of Greenwich

- **Severity:** S3
- **Class:** C11
- **Confidence:** high
- **Where:** `web/src/components/EpisodeList.tsx:365` (`airDate`)
- **Failure:** An episode that aired on 13 April 1999 is listed as "Apr 12, 1999" for anybody in the Americas. The server stores a calendar date as midnight **UTC** (`time.Parse("2006-01-02", …)` in `internal/meta/tmdb/tmdb.go:1019` and `internal/meta/nfo/nfo.go:846`, which `nfo.go:754` reads back with `.UTC()`). `airDate` formats that instant in the viewer's local zone, which is the previous evening everywhere west of UTC. The comment above it says it is "built from local components for the reason every date here is", which is the C11 rule applied to the wrong kind of value: this is a date stored as UTC midnight, not an instant.
- **Evidence:** `TZ=America/New_York node -e 'const u=Date.UTC(1999,3,13)/1000; console.log(new Date(u*1000).toLocaleDateString(undefined,{year:"numeric",month:"short",day:"numeric"}))'` prints `Apr 12, 1999`.
- **Fix sketch:** Format with `timeZone: "UTC"`, which reads the stored date back as the date it was. `released_at` is shown nowhere else in the client.

## R16-4 Your own star rating is drawn in gold at rest

- **Severity:** S3
- **Class:** C18
- **Confidence:** high
- **Where:** `web/src/components/RateItem.css:50` and `:56`, applied at `RateItem.tsx:40` and `:67`
- **Failure:** Rate a film four stars. Every time its detail page is opened, four full-strength gold stars sit on it while focus is somewhere else. Gold then means "your rating" as well as "where you are", which `docs/design.md` forbids by name ("Never use it for favorite… or any other state"). `QuickRate.css:22` shows the intended rule: its stars light only under the pointer or focus, and its comment says so. `RateItem` uses the saved score for the same class: `score = hover ?? rating?.score ?? 0`.
- **Evidence:** `.rate__star.is-full { color: var(--gold); }`; `is-full` is set from `score`, which falls back to the saved `rating.score` when nothing is hovered.
- **Fix sketch:** Draw a saved score in `--text-primary` (as `TagItem`'s set heart does, `TagItem.css:49`), and keep gold for the hover preview and focus.
